= Oracle DatabaseワークロードをNetApp Backup and Recoveryで復元する
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
スナップショット、セカンダリ システム上のレプリケートされたバックアップ、またはオブジェクトストレージに保存されているバックアップから Oracle Database ワークロードを復元するには、NetApp Backup and Recovery を使用します。

.これらの場所から復元
異なる開始場所からデータベースを復元できます。

* プライマリロケーション（ローカルスナップショット）からの復元
* セカンダリストレージ上の複製されたリソースから復元する
* オブジェクトストレージバックアップからの復元


.これらのポイントに復元する
データベースを元の場所にリストアすることも、別の登録済みホスト（代替場所）に新しいデータベースとしてリストアすることもできます。

* 元の場所に復元する
* 別の場所（別の登録済みホスト）にリストアする




[[how-oracle-database-restore-works]]
== Oracleデータベースのリストアの仕組み

Oracle Database のワークロードを復元すると、次のことが発生します：

* ローカル スナップショットからデータベースを復元すると、 NetApp Backup and Recovery はバックアップのデータを使用して新しいリソースを作成します。
* 複製されたストレージから復元する場合は、元の場所に復元できます。
* 別の場所にリストアする場合、NetApp Backup and Recoveryは、選択したソースデータベースのバックアップを、別の登録済みホスト上に新しいデータベースとしてリストアします。ターゲットホストと新しいデータベースの名前を指定します。リストア仕様ファイルを指定しない場合、Backup and Recoveryは、ターゲットホスト上のデータファイル、制御ファイル、およびREDOログファイルの場所を自動的に計算します。
* オブジェクト ストレージからバックアップを復元する場合、データをソース ストレージまたはオンプレミスのONTAPシステムに復元し、そこからデータベースを回復できます。




[[view-information-about-available-oracle-database-restore-points]]
== 利用可能なOracle Databaseのリストアポイントに関する情報を表示します

SCN番号や関連するデータベースのインカーネーションなど、利用可能な復元ポイントを表示します。


NOTE: Oracle Databaseは、 `RESETLOGS`オプションを使用してデータベースを開くたびに、新しいデータベースインカーネーションを作成します。NetApp Backup and Recoveryは、リストアポイントを確認する際や特定のSCNにリストアする際に、関連するデータベースインカーネーションを表示します。

.手順
. Backup and Recoveryメニューから、*Inventory*を選択します。
. NetApp Backup and Recoveryメニューから、[復元] を選択します。
. Oracle Databaseワークロードの *表示* を選択します。
. *データベース*タブを選択します。
. 復元ポイントを表示するデータベースの「アクション」image:icon-action.png["アクションアイコン"]アイコンを選択し、「保護の詳細を表示」を選択します。
. 利用可能な復元ポイントと、それぞれの復元ポイントに関連付けられているSCN番号およびデータベースのインカーネーションを確認してください。




[[restore-an-oracle-database]]
== Oracleデータベースを復元する

必要に応じて、Oracleデータベースを特定の時点、特定のシステム変更番号（SCN）、または最後に正常に動作していた状態に復元できます。また、スナップショットからデータベースを復元して、自動リカバリプロセスをスキップすることもできます。たとえば、手動でリカバリを実行したい場合などに利用できます。データベースは、その名前で検索することも、特定のフィルターを使用して検索することもできます。

*必須NetApp Console ロール* バックアップおよびリカバリのスーパー管理者、またはバックアップおよびリカバリのリストア管理者ロール。 https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["すべてのサービスに対するNetApp Consoleのアクセスロールについて学習します"^]

[[alternate-location-support]]
.開始する前に
別の場所にリストアする場合は、以下のサポートされているリストアシナリオとサポートされていないリストアシナリオに注意してください：

*サポート対象の代替ロケーションへのリストアシナリオ*

* 単一のOracleデータベース全体を単一のターゲットホストにリストアする
* 特定の時点、特定のSCN、または最新のバックアップへのリカバリ
* 選択したリカバリポイントに必要なアーカイブログがバックアップに含まれていない場合は、外部アーカイブログディレクトリを使用する


*サポート対象外の代替ロケーションリストアシナリオ*

* PDB内の表領域のリストアを含む、表領域のみのリストア
* 別のコンテナデータベース（CDB）へのPDBのみのリストア
* セカンダリストレージからのリストア
* オブジェクトストレージからのリストア


[NOTE]
====
PDBまたはテーブルスペースを特定のポイントインタイムまたはSCNにリストアする場合：

* PDBを1つだけ選択してください。ポイントインタイムリカバリは、複数のPDBのリストアとは互換性がありません。
* `PDB$SEED`はポイントインタイムリカバリに選択できません。
* コントロールファイルのリストアは、PDBまたはPDBテーブルスペースのポイントインタイムリカバリと組み合わせることはできません。
*  `SYSTEM`、 `SYSAUX`、および `UNDO`テーブルスペースは選択できません。


====
*Oracle Data Guardデータベースの復元に関する重要な注意事項*

* 復元する前に、データベースの役割が最新であることを確認してください。スイッチオーバーまたはフェイルオーバーが発生した場合は、まず *Hosts* タブを選択し、該当ホストの *Refresh* を選択してください。利用可能な復元オプションは、データベースが現在担っている役割によって異なります。
* データベースが現在スタンバイ状態にある場合、バックアップ取得時の役割に関係なく、元の場所に復元することはできません。別の場所に復元してください。
* データベースが現在スタンバイ状態の場合、セカンダリストレージまたはオブジェクトストレージにのみ存在するスナップショットを復元することはできません。
* データベースがスタンバイ状態だったときに取得したバックアップは、データベースがプライマリになった後に元の場所に復元できます。



CAUTION: プライマリデータベースをリストアしても、スタンバイは変更されません。ポイントインタイムまたはSCNリストアのあとに `RESETLOGS`を使用してプライマリを開くと、新しいデータベースインカネーションが開始されます。スタンバイがすでにその時点以降のREDOを適用している場合、スタンバイでのREDO適用はエラーで停止し、スタンバイは以前の状態のままになります。保護を再開するには、リストア後にOracleツールを使用してスタンバイを再確立します。

.手順
. NetApp Consoleメニューから、*保護 > バックアップとリカバリ* を選択します。
. NetApp Backup and Recoveryメニューから、[復元] を選択します。
. 名前検索フィールドの右側にあるドロップダウン リストから、*Oracle* を選択します。
. 復元するデータベースの名前を入力するか、復元するデータベースが配置されているデータベース ホストをフィルターします。
+
検索条件に一致するスナップショットのリストが表示されます。

. 復元するデータベースの*復元*ボタンを選択します。
. 復元オプションを選択します:
+
[role="tabbed-block"]
====
.特定の時点に復元する
--
.. *特定の時点に復元*を選択します。
.. *次へ*を選択します。
.. ドロップダウンから日付を選択し、「*検索*」を選択します。
+
指定された日時から最も近い時点のスナップショットが表示されます。

.. スナップショットが複数の場所に保存されている場合は、使用するソースの場所を選択し、場所の詳細を追加または確認してください。
.. *次へ*を選択します。


--
.特定のシステム変更番号 (SCN) に復元する
--
.. 利用可能なSCNと関連するデータベースのインカーネーションを確認するには、必要に応じて<<利用可能なOracle Databaseのリストアポイントに関する情報を表示します>>を参照してください。
.. *特定のシステム変更番号 (SCN) に復元*を選択します。
.. *次へ*を選択します。
.. 復元ポイントとして使用する SCN を入力し、[検索] を選択します。
+
指定されたSCNに最も近いスナップショットが表示されます。複数のデータベースインカネーションがSCNに一致する場合、一致するすべてのインカネーションが表示されます。

.. 複数のデータベースインカネーションが検索に一致する場合は、正しいインカネーションのスナップショットを選択してください。
.. スナップショットが複数の場所に保存されている場合は、使用するソースの場所を選択し、場所の詳細を追加または確認してください。
.. *次へ*を選択します。


--
.最新のバックアップ（最後の正常な状態）に復元する
--
.. *最新のバックアップに復元*を選択します。
.. *次へ*を選択します。
+
最新のスナップショットが表示されます。リストア操作では、利用可能なすべてのログバックアップを使用して、最後に正常だった状態をリカバリします。

.. スナップショットが複数の場所に保存されている場合は、使用するソースの場所を選択し、場所の詳細を追加または確認してください。
.. *次へ*を選択します。


--
.リカバリなしでスナップショットから復元
--
.. *リカバリなしでスナップショットから復元*を選択します。
+
このオプションを選択すると、データベースはスナップショットからリストアされますが、リカバリはスキップされます（ログバックアップは適用されません）。

.. *次へ*を選択します。
+
利用可能なスナップショットが表示されます。

.. リストからスナップショットを選択し、*次へ*を選択します。
.. スナップショットが複数の場所に保存されている場合は、使用するソースの場所を選択し、場所の詳細を追加または確認してください。
.. *次へ*を選択します。


--
====
. 復元先と設定を選択します。
+
[role="tabbed-block"]
====
.元の場所へのリストア
--
.. 「宛先設定」セクションで、以下の操作を行います。
+
... RACデータベースの場合は、リストアを実行するRACノードを選択してください。このオプションはRACデータベースでのみ表示されます。
... 復元する項目を選択してください：
+
**** *[すべてのデータファイル]* を選択すると、データベース全体またはコンテナデータベース（CDB）が復元されます。
**** コンテナ内の他の PDB に影響を与えることなく、CDB から 1 つ以上の PDB を復元するには、*プラガブル データベース （PDB）* を選択します。次に、リストから PDB を選択します。
**** 特定の PDB テーブルスペースを復元するには、*「プラガブル データベース （PDB） テーブルスペース」*（CDB 以外のデータベースの場合は *「テーブルスペース」* と表示されます）を選択します。次に、PDB とテーブルスペースを選択します。


... 必要に応じて、「制御ファイル」オプションを有効にすると、データベースの制御ファイルも復元されます。このオプションは、PDBまたはPDBテーブルスペースのポイントインタイムまたはSCNリカバリには選択できません。
... 必要に応じて、「復元およびリカバリに必要な場合にデータベースの状態を変更する」オプションを有効にすると、Backup and Recoveryがリカバリの種類に応じてデータベースの状態を管理できるようになります。
... オプションで、バックアップ後に新しいデータファイルが追加された場合、またはLVMディスク グループでLUNが追加、削除、または再作成された場合にIn Placeリストアを実行するには、*Force in place restore*オプションを有効にします。これにより、外部ファイルのチェックが上書きされ、選択したリストアオプションを使用してデータベース リカバリが続行されます。
... データベースを特定の時点またはSCNにリストアする場合で、アーカイブログが設定済みの場所にないときは、*Specify external archive log files locations*フィールドに外部アーカイブログファイルの場所を指定します。 `/`で始まるファイルシステムパス、または `+`で始まるASMディスク グループを入力します。テキスト入力フィールドの横にある「プラス」および「マイナス」ボタンを使用して、場所を追加または削除します。リカバリなしでスナップショットからリストアする場合、このフィールドは表示されません。
... 必要に応じて、「リカバリ後にデータベースまたはコンテナデータベースを読み書きモードで開く」オプションを有効にし、リストア範囲に一致するサブオプションを選択します（これらのオプションは、リカバリなしのスナップショットからリストアする場合は表示されません）：
+
**** *すべてのデータファイル*：リカバリ後、データベースまたはコンテナデータベースを READ-WRITE モードで開きます。
**** *PDBまたはPDBテーブルスペース*：リカバリ後、プラガブルデータベースを READ-WRITE モードで開きます。
**** *非CDBテーブルスペース*：リカバリ後にテーブルスペースをオンラインにします。




.. 「Prescripts and postscripts」セクションで、以下の操作を行ってください。
+
... *Prescript*：必要に応じて、このオプションを有効にして、リストア操作の前に実行するスクリプトの完全パスと、そのスクリプトが受け取る引数を入力します。
... *Postscript*: 必要に応じて、このオプションを有効にし、復元操作後に実行するスクリプトの完全なパスと、スクリプトが受け取る引数を入力します。
... スクリプトのタイムアウト値を選択してください。スクリプトがこの時間内に実行されなかった場合でも、復元処理は続行されます。




--
.別の場所へのリストア
--
別の登録済みホスト上に、データベースを新しいデータベースとしてリストアします。開始する前に、<<alternate-location-support,サポート対象シナリオとサポート対象外シナリオ>>を確認してください。

.. 「宛先設定」セクションで、以下の情報を入力してください：
+
... *ターゲットホスト*：新しいデータベースを作成する登録済みホストを選択してください。
... *対象データベース*：対象データベースの名前を入力してください。デフォルトでは、名前はソースデータベースの名前で始まりますが、編集することも可能です。
... *ターゲットデータベースパラメータのカスタマイズ*：このオプションを有効にすると、カスタムリストア仕様ファイルをアップロードして、ターゲットデータベースパラメータをカスタマイズできます。
... *リストア仕様ファイル*：*ターゲットデータベースパラメータのカスタマイズ*オプションを有効にした場合は、リストアされたファイルがターゲットホスト上のどこに配置されるかを制御するためのリストア仕様ファイルを指定します。デフォルトのリストア仕様ファイルをダウンロードし、認証やログの場所など、ターゲットデータベースの詳細を変更するようにカスタマイズできます。
+
リストア仕様ファイルを指定しない場合、Backup and Recoveryはデータファイル、制御ファイル、およびREDOログファイルの場所を自動的に計算します。

... データベースを特定の時点またはSCNにリストアする場合で、アーカイブログが設定済みの場所にないときは、*Specify external archive log files locations*フィールドに外部アーカイブログファイルの場所を指定します。 `/`で始まるファイルシステムパス、または `+`で始まるASMディスク グループを入力します。テキスト入力フィールドの横にある「プラス」および「マイナス」ボタンを使用して、場所を追加または削除します。リカバリなしでスナップショットからリストアする場合、このフィールドは表示されません。
... 必要に応じて、「リカバリ後にデータベースまたはコンテナデータベースを読み書きモードで開く」オプションを有効にし、リストア範囲に一致するサブオプションを選択します（これらのオプションは、リカバリなしのスナップショットからリストアする場合は表示されません）：




--
====
. *復元*を選択します。
+
リストア操作が完了したら、*Inventory*ページを確認し、新しいデータベースがリストに表示されていることを確認してください。データベースが表示されない場合は、ターゲットホストを更新してください。
