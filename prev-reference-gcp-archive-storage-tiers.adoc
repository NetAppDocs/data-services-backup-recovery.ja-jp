NetApp Backup and Recoveryは、古いバックアップ用のGoogle Cloud Storage Archive階層をサポートしています。この階層におけるバックアップのリストアコストと取得時間についてご確認ください。



[[supported-google-archival-storage-classes-for-netapp-backup-and-recovery]]
== NetApp Backup and Recoveryでサポートされている Google アーカイブ ストレージ クラス

バックアップファイルが最初に作成されると、それらは_Standard_ストレージに保存されます。この階層は、アクセス頻度の低いデータの保存に最適化されていますが、即時アクセスも可能です。

オンプレミスクラスタでONTAP 9.12.1以降を使用している場合は、さらなるコスト最適化のために、一定の日数（通常は30日以上）が経過したあとに、NetApp Backup and Recovery UIで古いバックアップを_Archive_ストレージに階層化できます。この階層のデータは取得コストが高いため、これらのアーカイブされたバックアップファイルからデータをリストアする必要がある頻度を考慮してください。アーカイブストレージからのデータのリストアについては、このページの該当セクションを参照してください。

このタイプのライフサイクルルールを使用してNetApp Backup and Recoveryを設定する場合は、Googleアカウントでバケットを設定する際にライフサイクルルールを設定しないでください。

https://cloud.google.com/storage/docs/storage-classes["Google のストレージ クラスについて学ぶ"^]。



[[restore-data-from-archival-storage]]
== アーカイブストレージからデータを復元する

古いバックアップファイルをアーカイブストレージに保存する方が、標準ストレージに保存するよりもはるかに安価です。ただし、アーカイブストレージに保存されたバックアップファイルからデータを復元するには、若干時間がかかり、費用も高くなります。

Google アーカイブからデータを復元するにはいくらかかりますか?:: Google Cloud Storageの地域別の料金の詳細については、 https://cloud.google.com/storage/pricing["Google Cloud Storage の料金ページ"^] 。
Google アーカイブにアーカイブされたオブジェクトの復元にはどのくらいの時間がかかりますか?:: 全体のリストア時間は2つの部分から構成されます：
+
--
* *取得時間*: アーカイブからバックアップ ファイルを取得して標準ストレージに配置する時間。これは「再水和」時間と呼ばれることもあります。他のクラウド プロバイダーが提供する「最も冷たい」ストレージ ソリューションとは異なり、データには数ミリ秒以内にアクセスできます。
* *リストア時間*：標準ストレージ内のバックアップファイルからデータをリストアするのにかかる時間。この時間は、アーカイブ階層を使用しない場合の、標準ストレージから直接実行する通常のリストアと同じです。


--


[NOTE]
====
アーカイブストレージからボリュームやファイルを復元するには、追加の時間がかかる場合があります。バックアップとリカバリが選択された優先度に基づいて復元を再試行している間、ジョブモニターではジョブは「進行中」のままになります。復元処理は「ジョブモニター」で監視します。すべての再試行後、ジョブが「完了」または「失敗」などの最終ステータスに達すると、復元処理は完了します。最終的にジョブが失敗しない限り、別の復元を開始しないでください。
