= NetApp Backup and Recoveryを使用してONTAPボリュームのワークロードを保護する
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Backup and Recoveryを使用して、ONTAPボリューム データを保護およびリストアし、バックアップを長期アーカイブします。2つの異なるストレージ システム上のソース データの3つのコピーと、クラウド上の1つのコピーを使用して、3-2-1戦略を実装できます。

システムの保護を有効にすると、Backup and Recoveryはボリュームのブロックレベルの永久増分コピーを作成します。ソースボリュームに加えて、以下のものがあります：

* ソースシステム上のボリュームのスナップショット
* 別のONTAPストレージシステム上の複製ボリューム
* オブジェクトストレージ内のボリュームのバックアップ


image:diagram-321-overview-unified.png["バックアップファイルが、ソースシステム上ではスナップショットとして、セカンダリストレージシステム上では複製ボリュームとして、そしてオブジェクトストレージ内ではバックアップファイルとしてどのように存在するかを示す図。"]

3-2-1方式には、以下の利点があります：

* 複数のデータ コピーにより、内部および外部のサイバー セキュリティの脅威から保護されます。
* 異なるタイプのメディアを使用すると、1 つのタイプに障害が発生した場合でも回復しやすくなります。
* オンサイト コピーから迅速に復元し、オンサイト コピーが侵害された場合はオフサイト コピーを使用できます。


必要に応じて、いずれかのコピーから、_ボリューム_全体、_フォルダ_、または1つ以上の_ファイル_を、同じシステムまたは別のシステムに復元できます。



[[how-protection-for-ontap-volumes-works]]
== ONTAPボリュームの保護の仕組み

Cloud Volumes ONTAPまたはオンプレミスのONTAPシステムでバックアップとリカバリを有効にすると、サービスはボリュームデータの完全なベースライン転送を実行します。その後の転送はすべて増分になります：変更されたブロックと新しいブロックのみが転送されるため、ネットワーク トラフィックは最小限に抑えられます。

Backup and Recoveryは、ONTAPのSnapMirrorテクノロジを使用してコピーの同期を維持します。ソースボリューム上にスナップショットを作成し、それをレプリケーション先とバックアップ先に転送します。オブジェクトストレージへのバックアップは、 https://docs.netapp.com/us-en/ontap/concepts/snapmirror-cloud-backups-object-store-concept.html["NetApp SnapMirrorクラウドテクノロジー"^]を基盤としています。

image:diagram-backup-recovery-general.png["NetApp Backup and Recovery が、ソース システム上のボリューム、および複製されたボリュームとバックアップ ファイルが保存されているセカンダリ ストレージ システムと宛先オブジェクト ストレージと通信する方法を示す図。"]

この図は、ボリュームがCloud Volumes ONTAPシステムにレプリケートされる様子を示していますが、オンプレミスのONTAPシステムにボリュームをレプリケートすることもできます。

各種類のコピーはそれぞれ異なる場所に保存されています：

* _スナップショット_ はソース システムのソース ボリュームに存在します。
* _複製ボリューム_はセカンダリ ストレージ システムに配置されます。これは、Cloud Volumes ONTAPまたはオンプレミスのONTAPシステムになります。
* _バックアップコピー_は、クラウドアカウント内のオブジェクトストア、またはオンプレミスに配置されます。Consoleは、クラスタごとに1つのオブジェクトストアを作成します。Consoleがオブジェクトストアを作成して名前を付ける方法の詳細については、link:concept-backup-to-cloud.html#where-backups-reside-in-object-store-locations["オブジェクトストア内のバックアップの保存場所"]を参照してください。



CAUTION: ストレージシステムやクラウド プロバイダ環境から直接バックアップ ファイルを管理したり変更したりしないでください。そうするとファイルが破損し、サポートされていない構成になる可能性があります。

使用するコピーとアーキテクチャを計画するには、link:prev-ontap-protect-journey.html["ONTAPボリューム保護の計画"]を参照してください。



[[features]]
== 機能

*複製*

* バックアップと災害復旧をサポートするために、 ONTAPストレージ システム間でデータを複製します。
* 一度に複数のFlexVolボリュームをセカンダリ システムに複製します。
* 2つのシステム間で事前共有鍵（PSK）を使用したONTAPネイティブの転送中暗号化を使用します。
* 転送失敗時には自己修復レプリケーションを利用します。
* レプリケートされたボリュームを、ソースシステムまたは別のシステムに復元します。


Backup and Recoveryを使用したレプリケーション時に利用できない https://docs.netapp.com/us-en/data-services-replication/index.html["NetApp Replication"^]の機能については、link:br-reference-limitations.html#replication-limitations-for-ontap-volumes["ONTAPボリュームのレプリケーションの制限"]を参照してください。

*オブジェクトストレージへのバックアップ*

* オンプレミスまたはクラウドシステムからパブリックまたはプライベートクラウドの低コストのオブジェクトストレージに、ボリュームの独立したコピーをバックアップします。
* 単一のバックアップ ポリシーをクラスタ内のすべてのボリュームに適用したり、固有のリカバリポイント目標を持つボリュームに異なるポリシーを割り当てたり、クラスタ内の将来のすべてのボリュームに適用されるポリシーを作成したりできます。link:prev-ontap-policy-manage.html["ONTAPボリュームのポリシーの管理"]を参照してください。
* DataLockとランサムウェアスキャンを使用して、バックアップを削除やランサムウェアから保護します。link:prev-ontap-policy-object-options.html#datalock-and-ransomware-protection-options["DataLockとランサムウェア保護オプション"]を参照してください。
* コストを削減するために、古いバックアップをアーカイブストレージに階層化します。link:prev-ontap-policy-object-options.html#archival-storage-options["アーカイブ保存オプション"] を参照してください。
* バックアップ関係を削除することで、バックアップを保持したままソースボリュームを廃止できます。
* 1つのボリュームにつき最大4,000個のバックアップを保持できます。
* 保存時はAES-256ビット暗号化、転送時はTLS 1.2 HTTPS接続でバックアップ データを保護するか、デフォルトのクラウド プロバイダのキーの代わりにお客様が管理する独自のキーを使用します。


*復元*

* ローカルスナップショット、レプリケートボリューム、またはオブジェクトストレージ内のバックアップから、特定の時点のデータを復元します。
* ボリューム、フォルダ、または個々のファイルを、ソースシステム、または別のシステム（異なるサブスクリプションやアカウントを使用しているシステム、または異なるリージョンにあるシステムを含む）にリストアします。
* 災害復旧時など、ボリュームへのアクセスをできるだけ早く提供する必要がある場合は、オブジェクトストレージからCloud Volumes ONTAPまたはオンプレミスシステムへのボリュームの_クイックリストア_を実行します。
* ブロックレベルでデータを指定した場所に直接復元し、元のACLを保持します。
* ファイルカタログを参照または検索して、復元する個々のフォルダとファイルを選択します。


復元オプションについては、link:prev-ontap-restore.html["ONTAPボリュームのワークロードを復元する"]を参照してください。



[[supported-volumes]]
== サポートされているボリューム

NetApp Backup and Recovery は、次のタイプのボリュームをサポートしています。

* FlexVol読み取り/書き込みボリューム
* FlexGroupボリューム（ ONTAP 9.12.1以降が必要）
* SnapLock Enterpriseボリューム（ ONTAP 9.11.1 以降が必要）
* SnapLock Compliance（オンプレミスボリューム向け）（ONTAP 9.14以降が必要）
* SnapMirrorデータ保護（DP）宛先ボリューム



NOTE: NetApp Backup and Recovery は、 FlexCacheボリュームのバックアップをサポートしていません。

Backup and Recoveryがサポートするソース システム、セカンダリ システム、オブジェクト ストレージの保存先、リストア先、およびリージョンについては、link:br-start-sources-destinations.html["NetApp Backup and Recoveryでサポートされているバックアップおよびリストア先"]を参照してください。追加の要件と制限については、link:br-reference-limitations.html["ONTAPボリュームのNetApp Backup and Recoveryの既知の制限"]を参照してください。



[[cost-and-licensing]]
== コストとライセンス

スナップショットやレプリケートボリュームを作成する際に発生する費用は、使用するディスク容量以外には一切かかりません。クラウド プロバイダからのリソース料金およびNetAppからのサービス料金は、オブジェクトストレージへのバックアップにのみ適用されます。

コストとライセンスオプションの詳細については、link:concept-backup-to-cloud.html#cost["NetApp Backup and Recoveryについて学ぶ"]およびlink:br-start-licensing.html["ライセンスの設定"]を参照してください。
